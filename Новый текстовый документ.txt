1. Описание системы

Название: Notion

Ссылка: https://www.notion.so/

Назначение:
Notion — цифровой SaaS-сервис для создания, редактирования и организации информации в виде страниц и блоков. Пользователь может создавать страницы, добавлять текст, заголовки и другие типы содержимого, а также структурировать информацию внутри рабочего пространства.

Целевая аудитория:
Сервис предназначен для пользователей, которым необходимо создавать и организовывать информацию в цифровом виде. Notion может использоваться для ведения заметок, хранения учебных материалов, планирования задач, создания документов и структурирования различной информации.

Основные возможности:

создание и редактирование страниц;
добавление текстовых блоков;
создание заголовков и других типов блоков;
организация информации внутри рабочего пространства;
редактирование содержимого непосредственно в браузере;
совместная работа с информацией и страницами.

Выбранный сценарий:
Создание страницы и добавление блока.

В рамках лабораторной работы рассматривается взаимодействие пользователя с сервисом Notion при создании новой страницы и добавлении содержимого, а также работа клиентской части приложения и её взаимодействие с серверной частью.

3. Анализ клиентской части системы

Клиентская часть Notion работает в браузере и отвечает за отображение интерфейса, обработку действий пользователя и редактирование содержимого страницы.

Для исследования клиентской части были использованы встроенные инструменты разработчика браузера DevTools.

В ходе исследования были рассмотрены HTML-структура элементов интерфейса и их атрибуты.

3.1. Анализ HTML-структуры

В DevTools был исследован HTML-элемент заголовка страницы Notion.

Для заголовка используется HTML-элемент:

<h1>

У элемента присутствует класс:

content-editable-leaf-rtl notion-page-block

Также были обнаружены следующие атрибуты:

contenteditable="true"
placeholder="New page"
data-content-editable-leaf="true"
aria-multiline="true"
aria-label="page title"
spellcheck="true"

Атрибут contenteditable="true" указывает на возможность редактирования содержимого элемента непосредственно пользователем в браузере.

Таким образом, заголовок страницы реализован как редактируемый HTML-элемент клиентской части приложения.

Исследование блока содержимого

Также был исследован элемент блока, созданного внутри страницы.

В исследуемом случае элемент представлен как:

<h2>

Для него используется тот же класс:

content-editable-leaf-rtl notion-page-block

Были обнаружены следующие атрибуты:

contenteditable="true"
placeholder="Heading 1"
data-content-editable-leaf="true"
role="textbox"
aria-multiline="true"
aria-roledescription="heading level 1"
spellcheck="true"

Наличие contenteditable="true" показывает, что содержимое блока может непосредственно изменяться пользователем.

Атрибут role="textbox" характеризует элемент как область для ввода текста, а aria-roledescription="heading level 1" указывает на его назначение как заголовочного элемента.

3.2. Анализ сетевых запросов

В разделе Network был исследован запрос, выполняемый при изменении содержимого страницы Notion.

Основным исследуемым запросом является saveTransactionsFanout. Он выполняется после изменения содержимого страницы и связан с передачей данных об изменениях серверной части приложения.

JSON

Запрос выполняется по защищённому протоколу HTTPS. Сервер успешно обработал запрос и вернул статус 200 OK.

В разделе Payload было установлено, что тело запроса содержит объект с параметрами requestId и transactions.

В поле requestId передаётся идентификатор текущего запроса. Поле transactions содержит массив транзакций. В исследованном запросе было обнаружено несколько элементов массива, каждый из которых содержит идентификатор id и идентификатор рабочего пространства spaceId, а также другие внутренние параметры.

Таким образом, клиентская часть Notion передаёт серверу структурированную информацию об изменениях страницы. Это позволяет серверной части обработать действия пользователя и сохранить соответствующие изменения.

В разделе Response сервер вернул пустой JSON-объект:

{}

Это означает, что в теле ответа отсутствуют дополнительные данные. При этом статус 200 OK показывает, что запрос был успешно обработан.



Назначение скриншота: демонстрация ответа сервера на запрос saveTransactionsFanout.

4. Анализ серверной части и API

Серверная часть информационной системы отвечает за обработку запросов, поступающих от клиентского приложения, выполнение операций с данными и передачу результатов обратно клиенту.

В рамках исследования серверная часть Notion непосредственно не рассматривалась, так как она находится на стороне сервиса и недоступна пользователю через браузер. Поэтому её работа анализировалась по сетевым запросам, которые выполняет клиентская часть.

4.1. Анализ API

В разделе Network были обнаружены несколько API-запросов, выполняемых приложением Notion.

Основным запросом выбран:

POST https://app.notion.com/api/v3/saveTransactionsFanout

Данный запрос связан с передачей изменений страницы от клиентской части к серверу.

Также были обнаружены следующие запросы:

POST https://app.notion.com/api/v3/detectPageLanguage
POST https://app.notion.com/api/v3/getAssetsJsonV2

Результаты исследования представлены в таблице.

Запрос	Метод	Назначение	Статус
/api/v3/saveTransactionsFanout	POST	Передача изменений страницы и её содержимого	200 OK
/api/v3/detectPageLanguage	POST	Определение языка содержимого страницы	200 OK
/api/v3/getAssetsJsonV2	POST	Получение информации о ресурсах и данных, необходимых клиентской части	200 OK

Все исследованные запросы выполняются по протоколу HTTPS и обращаются к домену app.notion.com.

Назначение скриншота: демонстрация URL запроса, HTTP-метода POST и статуса 200 OK.

4.2. Передаваемые данные

В ходе анализа запроса saveTransactionsFanout была исследована его полезная нагрузка.

В теле запроса присутствуют следующие основные параметры:

requestId
transactions

Параметр requestId содержит идентификатор запроса.

Параметр transactions представляет собой массив транзакций. В исследованном запросе было обнаружено несколько элементов данного массива. Каждый элемент содержит внутренний идентификатор id, идентификатор рабочего пространства spaceId и другие параметры.

Таким образом, клиентская часть передаёт серверу структурированную информацию об изменениях, выполненных пользователем.

Назначение скриншота: демонстрация параметров requestId и transactions, передаваемых серверной части.

Назначение скриншота: демонстрация статуса успешного выполнения запроса и содержимого ответа сервера.
